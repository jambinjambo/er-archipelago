## What this repo is

Elden Ring as an Archipelago multiworld game, in **three pieces joined by one seam**:

| Piece | Lives in | Language | Runs when |
|---|---|---|---|
| **Data derivation** | `greenfield/gen_data.py` + `tools/datamine_*.py` | Python | offline, on a box with `elden_ring_artifacts/` |
| **The apworld** | `greenfield/eldenring/` | Python (Archipelago world API) | at multiworld **generation** |
| **The runtime client** | `from-software-archipelago-clients/` (git submodule) | Rust (`cdylib`) | in the **game process**, loaded by ModEngine3 |

The seam is **`slot_data`**: a JSON blob the apworld emits at generation and the
client reads at connect. Every key is declared once in
`greenfield/eldenring/contract.py`; `greenfield/CONTRACT.md` is its generated,
human-readable form with the Rust consumer named per key.

**Pure runtime.** The game stays vanilla on disk — no `regulation.bin` patching,
nothing baked per seed. If a change would require writing game files, it is the
wrong change for this project.

## Rules that cause silent breakage if ignored

1. **Never hand-edit a generated module.** They carry
   `AUTO-GENERATED by greenfield/gen_data.py` on line 1 and a `_GEN_STAMP`
   naming their `inputs_hash`. CI regenerates and fails on a non-empty diff.
   Edit `gen_data.py` (or the curated `.tsv`) and regenerate.
2. **Do not add a phase to `core.py`.** One feature = one file in `features/`,
   self-registered with `@register`. Feature modules may import
   `..registry` / `Options` / `..data` / `..region_spine`, **never `..core`**
   (circular). See `features/README.md`.
3. **A slot_data key must be declared in `contract.py` first.**
   `registry.merge_slot_data` raises on an undeclared key — an undeclared
   emission is exactly how a feature goes silently dark client-side.
4. **The item pool is count-exact.** `core.create_items` computes
   `slots = total_locations - len(pool)` and fills the remainder. Anything a
   feature returns from `create_items` consumes a slot off the filler tail.
   `features/filler_budget.py` is the *single owner* of that tail — do not add a
   fourth pass that also spends it (that mistake is documented in its docstring).
5. **Option docstrings are player-facing text.** `tools/dump_options_metadata.py`
   dumps them verbatim into the wizard and AP's WebHost tooltip. Put rationale
   and history in `#` comments, never in the docstring.
6. **Do not move the RNG stream.** Draw order in `region_spine.compute_kept` and
   `core.create_items` is load-bearing: reordering a `rng.sample` changes every
   already-rolled seed. Appends go *after* the sample; several comments mark the
   exact lines.
7. **Provenance is a machine check, not an intention.** No game assets, no data
   or code from another randomizer (`thefifthmatt`'s especially — the codebase
   says "matt-free" throughout). `tools/check_integrity.py` greps for
   matt-lineage location-key grammar on every staged commit; see `PROVENANCE.md`
   for the five non-negotiables and the gate enforcing each.
8. **A check that can become permanently unreachable may not carry progression.**
   Three causes, one rule, enforced in `core._add_locations` via `item_rule`
   (never `LocationProgressType.EXCLUDED` — that routes into AP's excluded-fill
   pass and FillErrors on rule-carrying shop slots).

## Making common changes

| Task | Where |
|---|---|
| Add/adjust a player option | the owning `features/*.py` (`OPTIONS = {...}`), or `core.py` only if truly core |
| Add a new gameplay phase | one new `features/<name>.py` + `tests/test_gf_<name>.py`. No other file changes |
| Send new data to the client | add ONE `ContractKey` in `contract.py`, emit from the feature's `slot_data()`, regenerate `CONTRACT.md` via `greenfield/gen_contract.py` |
| Change which checks exist / their flags | `gen_data.py` or a curated `.tsv` — never `data.py` |
| Change region membership | `greenfield/region_groups.py` (bucket→region), then regenerate |
| Retire a yaml knob but keep the behaviour | `defaults.py` `FROZEN_OPTIONS` — the option class stays declared so the contract keeps being emitted |

## Traps this codebase has actually hit

- `random` cannot be a `Choice` option name (AP reserves it); an old value name
  must survive as `alias_*`, because `Choice.from_text` **raises** on an unknown
  value in a yaml already in the wild.
- `num_regions` is a **draw size, not a region count** — a named goal force-keeps
  regions and `REGION_PARENT` closure pulls ancestors in. `describe_kept()`
  exists solely because a player got 4 regions from `num_regions: 1`.
- `all()`/`any()` over an empty set passes vacuously. `tests/conftest.py` ships a
  quantifier-emptiness spy (`GF_QUANTIFIER_SPY=1`) for exactly this.
- A `Frozen` stand-in must expose `.visibility` — AP's spoiler writer reads it on
  every option of every world, and the crash lands *after* a successful fill.
- Region locks are only enforceable where play_region geometry is measured;
  unmeasured regions are excluded from the eligible pool with a warning rather
  than shipping a lock that does nothing (`core._eligible_regions`).
